Search Algorithms

A beginner-friendly guide to the algorithms used in this EV planner.

🔍

Breadth-First Search (BFS)

Unweighted · Layer-by-layer

BFS explores the graph level by level, visiting all nodes at distance 1 before distance 2, and so on. It uses a queue (FIFO).

✅ Advantages

Guaranteed to find the fewest-hop path. Simple to implement and complete when a path exists.

❌ Disadvantages

Ignores edge weights. A 500 km highway counts the same as a 10 km city road, making it unsuitable for weighted EV routing.

Queue: [start] → explore neighbours → repeat for each level

In this project: BFS is included for educational comparison. Because it ignores edge weights, it can return a path with fewer stops but greater total distance than Dijkstra or A*.

📐

Dijkstra's Algorithm

Weighted · Guaranteed Optimal

Dijkstra uses a min-heap priority queue and expands the node with the smallest accumulated cost. This finds the globally shortest-cost path.

Priority Queue: expand node with minimum g(n)
✅ Advantages

Guaranteed shortest-distance path. Works with positive edge weights and is suitable for weighted graphs.

❌ Disadvantages

Explores nodes in all directions without heuristic guidance. It can be slower than A* on large graphs.

Time complexity: O((V + E) log V)

In this project: Dijkstra finds the shortest-distance road path and typically explores more nodes than A* because it has no heuristic guidance.

🎯

Greedy Best-First Search

Heuristic-Only · Fast, Not Optimal

Greedy Best-First expands the node that looks closest to the goal according to the heuristic h(n), while ignoring the actual cost accumulated so far.

Priority = h(n) = haversine straight-line distance to goal
✅ Advantages

Very fast and explores fewer nodes than Dijkstra or A*. Useful when a quick approximate answer is needed.

❌ Disadvantages

Not guaranteed to find the optimal path. The heuristic can lead it toward a longer road path.

In this project: Greedy usually explores fewer nodes, but the resulting path can be longer than the shortest-distance path.

⭐

A* Search

Optimal + Efficient

A* combines the accumulated cost from the start with a heuristic estimate of the remaining cost.

f(n) = g(n) + h(n)
g(n) Actual accumulated cost from the start node to node n, including road distance, time, energy, etc.
h(n) Heuristic estimate of the remaining cost from n to the goal, using haversine straight-line distance.
✅ Advantages

Finds an optimal path and can explore fewer nodes than Dijkstra because the heuristic guides the search toward the goal.

❌ Disadvantages

More complex than Dijkstra. Performance depends on heuristic quality and memory usage can become high for large graphs.

🔋⭐

Battery-Aware A* Project Core Algorithm

EV-Specific · Handles Charging Stops

Standard A* tracks location. For EV route planning, the battery level must also be tracked.

State = (node_id, battery_percentage)

The algorithm supports two types of actions:

🚗 DRIVE Action

Move along a road edge. The algorithm checks whether the current battery can cover the distance, deducts the required energy, and creates a new state with reduced battery.

⚡ CHARGE Action

At a node with an available charging station, the battery can be charged to a higher level. Charging time and cost are added to the path cost.

Drive Charge Drive Charge Destination

The algorithm automatically plans the drive and charging sequence, choosing charging stops that minimise the total multi-objective cost.

total_cost = α·travel_time + β·charge_time + γ·charge_cost + δ·energy_consumed
